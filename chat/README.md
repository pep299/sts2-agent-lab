# ChatでMentorを使う

取得先が登録されたChatでは、次の一言で開始する。

```text
gh artifactからパッケージ取得してラン開始
```

既定値はv0.113.0・アイアンクラッド・A10・ランダムseed。指定された項目だけ上書きし、未指定の開始条件について確認を求めない。

```text
gh artifactからパッケージ取得してラン開始。サイレント、A5
gh artifactからパッケージ取得してラン開始。seed=7
```

### 取得先の初回登録

新しいチャットでも取得先を省略する場合は、ChatGPTプロジェクトの指示に以下を一度登録する。[プロジェクトの指示は同じプロジェクトのチャットに適用される](https://learn.chatgpt.com/docs/projects)。この会話内で取得先を伝えて使う場合は、プロジェクトへの登録は不要。

```text
「gh artifactからパッケージ取得してラン開始」と言われたら、GitHubのpep299/sts2-agent-labで、mainの最新の成功したMentorワークフローからmentor-chat artifactを取得・展開する。
同梱README.mdに従って新規ランを開始し、ユーザー指定の開始条件を既定値より優先する。
```

Chatは利用可能なGitHub接続ツールで取得する。取得できない場合はエラーを報告して停止する。ZIPが添付されていれば、それを展開して同梱READMEを使う。

再開する場合は、開始時と同じartifact ZIPと保存JSONを渡す。

```text
README.mdに従い、添付の保存JSONを再開して。
現在地、HP、デッキ、レリック、ポーション、選択肢を示して止めて。
```

## Chatの操作手順

Chatが行動を判断し、Mentorがゲームルールを適用する。以下の進行・表示の既定値よりユーザーの明示指示を優先する。

### 起動

artifactを展開し、展開先をPython 3.11以降のモジュール検索パスへ追加する。同梱の`mentor_chat.Session`を使用する。

| 操作口 | 用途 |
| --- | --- |
| `Session.start(...)` | 新規ランを開始する。未指定の引数には既定値を使う |
| `session.observe()` | 現在の状態・選択肢を取得する |
| `session.act(action)` | Mentorの行動辞書を実行し、前後の状態と戦闘ログを返す |
| `session.save(path)` | 開始条件と行動列をJSONへ保存する |
| `Session.load(path)` | 保存した開始条件と行動列で再開する |
| `session.fork(after_steps)` | 先頭N行動まで再生した別のSessionを作る。0は開始直後 |

開始条件の指定は`character`・`ascension_level`・`seed`・`game_version`等の引数へ渡す。「サイレント、A5」は`character`が`Silent`、`ascension_level`が`5`。文字列seedも渡せる。未指定の引数は渡さず、実行コードの既定値を使う。

最初にゲーム版・キャラクター・アセンション・実際に使用したseed・HP・所持金、現在Actのマップ画像とネオー等のエンシェントの全選択肢・効果を提示し、選択・移動前に停止する。開始条件は`session.config`から読み、seed未指定時の値も表示する。再開・分岐でseedを引き直さない。

### 取得・行動

- 進行には`session.act`を使い、`session.rm`は参照に使う。`take_action`・`force_*`・`debug_*`・`set_player`を直接呼ばない。`combat_state()`は複製なので、その`apply()`ではラン本体を進められない。
- 行動の直前に選択肢を取り直す。手札・敵・報酬の添字を前の行動から再利用しない。
- 戦闘中の現在HP・ブロック・エナジーは`state['combat']['player']`から読む。`run_hp`・`run_max_hp`は非戦闘時に使う。
- イベントは`state['event_options']`、休憩は`rest_options`、報酬は`card_reward`、ショップは`shop`を読む。カード削除・強化等の追加選択肢は`session.rm.card_removal_options()`・`smith_options()`等を参照する。
- v0.113.0の名前と説明は、同梱の`sts2-pycli/localization_eng_v0.113.0/`内の`cards.json`・`relics.json`・`potions.json`等を参照できる。キーは`BASH.title`・`BASH.description`等。未解決の`{変数}`を推測した数値で埋めず、別版の説明を流用しない。
- 操作例外や未対応処理は、行動辞書と直前状態を添えて報告し、そこで停止する。ゲーム効果をChat側で補って進めない。
- 学習方策や`random_playout`等に進行を任せず、各行動をChatが選ぶ。

### 停止する場所

- 初期マップ、エンシェント、イベント、休憩、ショップ、カード・レリック報酬で選択肢を提示して停止する。既に指定された選択やルートの範囲は実行してよい。
- 「次の戦闘」では、その戦闘を進めて終了後に内容と報酬を示す。途中に未指定のイベント・休憩・ショップがあれば選択前に止まる。
- 戦闘中のカード・対象・カード選択はChatが判断する。ターン数の短縮だけで決めず、被ダメージと資源の消費を考慮する。
- ポーションは許可された範囲で使う。許可がない状態で使いたい場合は、使用案と温存案を提示して止まる。

### 表示する内容

マップはエンジンのノードと接続から、列・行・部屋種別・現在地が読める接続線付き画像を表示する。列番号は`col`値で統一する。画像を表示できなければノードと接続の表を示す。

戦闘では次を示す。

1. 開始時：自分と敵全員のHP・ブロック・状態・意図、エナジー、デッキ、レリック、ポーション。
2. 各ターン：開始手札の全カードと現在コスト、敵意図、プレイ順・対象・追加ドロー・効果、実際の敵行動、終了時HPと資源。
3. 終了時：ターン数、HP変化、使用ポーション、残り資源、報酬の全選択肢。

根拠は`session.history`内の`before`・`after`・`combat_log`。`after['combat']`は非戦闘時には入らない。戦闘終了時の敵行動や効果は行動記録の`combat_log`を読む。`combat_log_dropped > 0`なら欠落を明記する。取得できない値や履歴を、結果から再構成しない。

### 分岐・保存再開

比較中は元のSessionを保持し、`fork`で作った別のSessionで変更案を実行する。変更行動・終了地点・HP・消耗品・デッキの差を示す。別案の採用が指示されたら、そのSessionを以降の進行に使い、採用中の保存JSONを更新する。

選択・戦闘終了・分岐採用後に保存し、返答で採用中の保存JSONへのダウンロードリンクを渡す。開始時のZIPへのリンクも渡し、**ZIPと保存JSONを両方保管**するよう伝える。公開artifactは更新時に削除されるため、保存JSONだけでは元の実行ファイルを取り戻せない。

再開は保存時のZIPを読み込み、`Session.load`で行動列を再生する。
